# SubseqHash3

SubseqHash3 generates DNA seeds designed to tolerate edits. It provides
`seeds-sub` for substitution-heavy data and `seeds-ind` for indel-heavy data.
Use `seeds-ind` if you are not sure.

## Build

Requires a C99 compiler (GCC or Clang), GNU Make, and a POSIX environment
with `getline` and `clock_gettime`. The test suite also requires Python 3.

```sh
make
make test
```

The executable is `build/subseqhash3`. Run `build/subseqhash3 --help` or
`build/subseqhash3 <command> --help` for usage. Use `CC`, `CFLAGS`, and
`BUILD_DIR` to customize the compiler, flags, and output directory.

The normal build uses scalar kernels. For an AVX-512F/BW/VL CPU:

```sh
make simd
make BUILD_DIR=build/simd \
  CFLAGS='-O3 -std=c99 -Wall -Wextra -Wpedantic -mavx512f -mavx512bw -mavx512vl -mtune=skylake-avx512' test
```

The SIMD binary requires compatible hardware; there is no runtime CPU dispatch.
All seeding is single-threaded.

## ABCk Tables

One set of ABCk tables defines k orders over length-k DNA strings. 
ABCk tables contain a paramether D, hash residues, which balances
the probability of hash-collision and runtime: large D yields
a higher probability of hash-collision at the cost of longer runtime.


The following command generates and saves random ABCk tables.

```text
build/subseqhash3 tables k D S OUTPUT [--seed SEED]
```

| Parameter | Meaning |
|:---|:---|
| `k` | maximum length of seed, 1–257.  |
| `D` | positive number of hash residues; need not be a power of two. |
| `S` | positive number of independent table sets to generate. |
| `OUTPUT` | destination binary table file. |
| `--seed SEED` | optional unsigned random seed for reproducible table generation. |

For example, generate 2 independent sets for seeds of length up to 8,
	where the hash residues is set to 64:

```sh
build/subseqhash3 tables 8 64 2 shared.piv --seed 42
```

The same file can be reused by both seeding modes (see below). 

## Seedings

Mode `seeds-sub` defines the neighbors of each length-W input window
as the set of strings by applying exactly 1 deletion and E substitutions to the window (each string
in the set is of length W-1).
Mode `seeds-sub` defines the neighbors of each length-W input window
as the set of strings by applying exactly E deletion to the window (each string
		in the set is of length W-E).
Then the smallest string in the set under each of the orders (given by the ABCk tables)
is computed and returned as the resulting seed. 
So, for `seeds-sub`, you can get up to W-1 seeds, 
and for `seeds-ind` you can get up to W-E seeds.
You may choose to keep R seeds, rather than
the total W seeds.

Use the following commands for seedings:

```text
build/subseqhash3 seeds-sub INPUT W E D R S OUTPUT [TABLE_FILE] [--inward] [--seed SEED]
build/subseqhash3 seeds-ind INPUT W E D R S OUTPUT [TABLE_FILE] [--inward] [--seed SEED]
```

| Parameter | Meaning |
|:---|:---|
| `INPUT` | DNA file with one nonempty A/C/G/T sequence per line, in either case. Each line must be at least W bases. |
| `W` | input window length. |
| `E` | exact substitution count for `seeds-sub`, or exact deletion count for `seeds-ind`. |
| `D` | positive number of hash residues, matching the table file. |
| `R` | number of orders to use from each table set. |
| `S` | positive number of independent table sets to use. |
| `OUTPUT` | destination seeding CSV file. |
| `TABLE_FILE` | optional reusable binary table file generated by `tables`. |
| `--inward` | use inward traversal instead of the default outward traversal; this changes scores and seeds. |
| `--seed SEED` | reproducible table creation when TABLE_FILE is omitted; cannot accompany TABLE_FILE. |

| command | window limits | edit budget | seed length | orders per set |
|:---|:---|:---|:---|:---|
| `seeds-sub` | 2<=W<=257 | 0<=E<W | W-1 | 1<=R<=W-1 |
| `seeds-ind` | 1<=W<=256 | 0<=E<W | W-E | 1<=R<=W-E |

Each window produces R*S seeds. 

For example, seed two sequences using the tables generated above:

```sh
printf '%s\n' ACGTACGTACGT ACGTTCGTACGT > input.seq
build/subseqhash3 seeds-sub input.seq 8 1 64 3 2 sub.csv shared.piv
build/subseqhash3 seeds-ind input.seq 8 1 64 3 2 ind.csv shared.piv
```

Each sequence has 5 length-8 windows, with 6 seeds per window (R = 3 and S = 2), so each CSV
contains 60 data rows plus a header. Both examples produce length-7 seeds.

Both seeding commands write the following CSV header:

```text
set,pivot,sequence,window_start,substitutions,deletions,seed,psi,omega
```

| Column | Meaning |
|:---|:---|
| `set` | zero-based independent table-set index. |
| `pivot` | zero-based distinguished order in the output seed. |
| `sequence` | zero-based input line index. |
| `window_start` | zero-based window offset within the input sequence. |
| `substitutions` | number of substitutions used: E for `seeds-sub`, 0 for `seeds-ind`. |
| `deletions` | number of deletions used: 1 for `seeds-sub`, E for `seeds-ind`. |
| `seed` | selected DNA seed, written in uppercase. |
| `psi`, `omega` | hash scores used to select the seed: minimize psi, then maximize omega. |
