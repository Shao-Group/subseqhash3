# Pivot seeds: repeats CLI and reusable tables

## Change summary

The pivot C API is now available through the `repeats` command, with reusable
tables generated by `tables --pivots` or automatically on first use. The new
versioned table format stores both side tables and pivot parameters, validates
them on load, and reconstructs the caches used by scalar and SIMD seeding.
The CLI writes CSV results for every sliding window and reuses one workspace
throughout the run. Legacy `tables`, `seeds`, and `collisions` retain their
existing format and behavior, with a corrected mask-copy length in the legacy
table writer. The build includes the new command and serialization code;
`make test` includes the new regression suite.

`repeats` exposes the optimized, single-threaded pivot C API. It generates
exactly **one deletion and E substitutions of retained bases**, returning R
seeds of length W-1 for each sliding window. This differs from `seeds`, whose
E is a total edit budget and which emits all substitution/deletion splits.

## Build and run

For an AVX-512F/BW/VL-capable CPU:

```sh
make simd
build/simd/subseqhash3 tables 30 1024 10 tables.piv --pivots --seed 42
build/simd/subseqhash3 repeats input.seq 30 5 1024 10 seeds.csv tables.piv
```

For the other focused configuration:

```sh
build/simd/subseqhash3 tables 50 1024 10 tables50.piv --pivots --seed 42
build/simd/subseqhash3 repeats input.seq 50 8 1024 10 seeds50.csv tables50.piv
```

Use `make` and `build/subseqhash3` for the scalar build. Both builds are
single-threaded. AVX-512 binaries require compatible hardware; there is no
runtime instruction-set dispatch. Help is available through `repeats --help`
and `tables --help`.

Input is one DNA sequence per line, not FASTA/FASTQ. Uppercase and lowercase
A/C/G/T and LF/CRLF line endings are accepted. Empty lines, non-DNA symbols
(including N), and sequences shorter than W are rejected. Windows advance
one base at a time, and all sequences use the same initialized table families.

## Command arguments

```text
subseqhash3 repeats INPUT W E D R OUTPUT [TABLE_FILE]
subseqhash3 tables n D R OUTPUT --pivots [--seed SEED]
```

`2<=W<=257`, `0<=E<=W-1`, `D>0`, and `R>0`. For pivot tables, n is the maximum
supported window length and must be 2..257. R is the requested number of seed
repetitions, **not** the number of independent table families. Each family
supplies k=W-1 related pivot orders. More than k repetitions use additional
independent families; the last family may be partial. Different orders can
return identical seed strings.

For matching n=W, `tables --pivots` stores `1+(R-1)/(W-1)` families. Thus n=30,
R=10 needs only one family; n=30,R=40 needs two. A stored family always includes
all n-1 pivot orders, even if only a few are requested. Reusing a file requires
`file.n>=W`, matching D, and at least `1+(R-1)/(W-1)` families. Shorter windows
can require more families for the same R; larger stored n alone does not
guarantee enough families.

`--seed` makes table generation reproducible. Reuse the same table file to
compare sequences under identical orders. E is not part of the table format:
the same tables support any valid substitution budget.

If TABLE_FILE is omitted, `repeats` generates fresh randomized pivot tables in
`OUTPUT.piv` and then uses them. To reproduce that run, pass the generated
file explicitly:

```sh
build/simd/subseqhash3 repeats input.seq 30 5 1024 10 first.csv
build/simd/subseqhash3 repeats input.seq 30 5 1024 10 again.csv first.csv.piv
```

These CSV files are identical for identical inputs. Automatic generation has
no explicit seed option; use `tables --pivots --seed` when a chosen seed is
needed. Existing table destinations can be replaced. The new command rejects
input/output/table aliases that would overwrite an input or active table.
Invalid table dimensions or formats are detected before opening OUTPUT.
Later input/I/O errors may leave a partial CSV; a successful exit is required
before consuming the complete result.

## CSV output

```text
repeat,family,pivot,sequence,window_start,substitutions,deletions,seed,psi,omega
```

Rows are sequence-major, then window-major, then repeat-major. Indices are
zero-based. For repeat r, `family=r/(W-1)` and `pivot=r%(W-1)`; numbering starts
again for each window. `sequence` identifies the input line, `window_start`
is its nucleotide offset, and `seed` is an uppercase DNA string of length W-1.
Every row has `substitutions=E` and `deletions=1`. Each order minimizes psi,
then maximizes omega; these are not the legacy seeds API's score conventions.
Source positions and substitution flags remain available through the C API
but are not included in this CSV.

For a sequence of length L, there are `(L-W+1)*R` rows. The command prints
end-to-end wall and CPU times to stderr, including table generation/loading
and file I/O. These are not isolated DP-kernel benchmark timings.

The command reuses one workspace across all windows, sequences, and families,
and frees each window's seed results after writing. It holds an encoded input
sequence and R results, not the results of every window at once.

## Legacy table compatibility

Default `tables n D R OUTPUT [--seed SEED]` retains its legacy behavior and
format: R independent table sets for `seeds`/`collisions`. Those files lack the
two side tables and pivot parameters, so they cannot supply the pivot orders.
Use `--pivots` to generate the separate format. Both readers reject the wrong
format; changing a filename extension does not convert it. Existing legacy
files remain readable, and existing seeds/collisions command syntax is unchanged.

The legacy writer's mask-copy length is corrected from `n*4*(D+31)/32` to
`n*4*((D+31)/32)`. This fixes the previously documented mask-buffer over-read
(including D=31 and D=32) without changing the file layout or legacy scoring.

## Pivot table format and API

`src/pivot_table_file.h` provides owned-array `create`, `open`, and `close`
functions. Unlike the legacy mmap loader, `open` allocates writable arrays.
Pass an empty file object and close it before reusing it. The C create
function's count is **families**, whereas the CLI R argument is repetitions.

Version 1 stores actual table parameters, not just a random seed. Its 64-byte
header contains eight-byte fields: magic `SQH3PIV\0`, version 1, maximum n,
D, family count, total byte size, generation seed, and a zero reserved field.
All multibyte integers are explicitly little-endian, independent of native
pointer/size_t size. Signs use signed two's-complement bytes.

For k=n-1, each family stores:

1. Left A, B1, B2 byte arrays, then C as 64-bit residues.
2. Right A, B1, B2 byte arrays, then C as 64-bit residues.
3. Pivot A, left signs, right signs as bytes, then pivot C as 64-bit residues.

Each side byte array has `4*k*D` entries; each C/pivot array has `4*k` entries.
Each family's byte size is `6*(4*k*D)+27*(4*k)`. Native pointers, padding,
signed-A caches, B1 masks, and wrap indices are not serialized. The loader
reconstructs these, including the reflected right-side SIMD caches, without
generating random tables first. Arrays needing vector alignment are allocated
with 64-byte alignment.

The reader validates magic/version, dimensions, exact file size, reserved
fields, sign/magnitude ranges, and residue bounds. This is structural
validation, not a cryptographic integrity check. Creation writes a same-directory
temporary file, flushes/syncs it, and renames it only after successful generation;
a failed create does not replace an existing destination.

## Verification

On 2026-10-20, `make test` passed with the default scalar build and
`-Wall -Wextra -Wpedantic`, including the built-in correctness tests and the
pivot table/CLI regression suite described below.

```sh
make test
make check-repeats
make BUILD_DIR=build/repeats-simd \
  CFLAGS='-O3 -std=c99 -Wall -Wextra -Wpedantic -mavx512f -mavx512bw -mavx512vl -mtune=skylake-avx512' \
  test check-one check-pivots check-pivots-single
```

The new tests compare every serialized array and reconstructed cache with
freshly generated families, and compare complete seed witnesses after loading.
They check CSV rows against direct C API calls across multiple sequences,
windows, and families; deterministic generation; automatic/reused tables;
E=0/W-1; W=2/257; malformed/truncated/oversized files; incompatible legacy files;
invalid input/arguments; and overwrite guards. Expected rejection diagnostics
are captured in `BUILD_DIR/repeats-test.log` by make and replayed on failure.
Temporary test files are created under /tmp and removed after successful checks.

Separate executable-level smoke tests used two 100-base input sequences at
R=10, D=1024. W=30/E=5 produced 1420 data rows and W=50/E=8 produced 1020;
the scalar and SIMD CSVs matched byte-for-byte in both configurations.

ASan/UBSan:

```sh
ASAN_OPTIONS=detect_leaks=0 make BUILD_DIR=build/repeats-sanitize \
  CFLAGS='-O1 -g -std=c99 -Wall -Wextra -Wpedantic -mavx512f -mavx512bw -mavx512vl -fsanitize=address,undefined -fno-omit-frame-pointer' \
  LDFLAGS='-fsanitize=address,undefined' test
```

Leak detection is disabled for this environment's tracing limitations; address
and undefined-behavior checks remain enabled.
