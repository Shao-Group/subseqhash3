# Focused r=10 comparison

Run date: 2026-10-20. The requested cases are n=30, E=5 and n=50, E=8,
each generating ten seeds. D=1024 is the primary configuration from the
earlier optimization work; D=31 is included as the SubseqHash2 paper's
typical small-residue configuration. E is passed unchanged to both APIs.

## Results

Times are microseconds per input window, including all ten seeds. The
primary pivot measurements include DP allocation, traceback, and cleanup.
Speedup is the ratio of the median simple-repeating time to the median
pivot-batch time, not the median of per-round ratios.

| n | E | D | Pivot batch | Simple repeating (10 calls) | Speedup |
|---:|---:|---:|---:|---:|---:|
| 30 | 5 | 1024 | 219.392 | 916.340 | 4.18x |
| 50 | 8 | 1024 | 453.010 | 2417.915 | 5.34x |
| 30 | 5 | 31 | 22.144 | 331.605 | 14.97x |
| 50 | 8 | 31 | 38.925 | 828.272 | 21.28x |

The reusable-workspace API measures 216.778 and 453.025 us at D=1024,
respectively, yielding 4.23x and 5.34x against simple repeating. It has
little effect on the larger case in this run; the primary table does not
rely on amortizing allocations across windows.

As a same-problem reference, invoking the new API separately for each of
the same ten pivots costs 1396.567 and 3470.136 us at D=1024. Sharing the
DP therefore provides 6.37x and 7.66x speedups over those separate calls.

## What is compared

- **Pivot batch:** `subseqhash3_compute_pivot_repeats()` with one table
  family and r=10, selecting pivots 0..9. Each seed has exactly **one
  deletion and E substitutions**, length n-1, and minimizes its pivot
  order's psi followed by maximizing omega.
- **Simple repeating:** ten calls to the previously implemented
  `subseqhash3_compute_one_substitution()`, using ten separately seeded
  table sets. Each seed has exactly **one substitution and E deletions**,
  length n-E, with the earlier largest-psi/largest-absolute-omega order.
- **Separate pivots:** ten single-pivot calls to the new API, matching
  the pivot batch's input, edit neighborhood, orders, and tables. This is
  the same-problem reference, rather than the previous function.
- **Workspace reuse:** the new repeat API with a persistent DP workspace,
  warmed once before the sample. Allocation of this workspace is outside
  the timed region; per-result allocation and cleanup remain inside.

The simple-repeating column is the requested comparison against the
previous implementation. Because the edit counts and orders differ, it
measures runtime only. It does not compare equal edit neighborhoods,
identical seeds, independent-hash quality, or collision probabilities.

## Measurement protocol

- Intel Xeon Gold 6148, one thread pinned to logical CPU 0 using `taskset`.
- GCC 13.3.0, both implementations linked from the same AVX-512 build.
- Flags: `-O3 -std=c99 -Wall -Wextra -Wpedantic -mavx512f -mavx512bw
  -mavx512vl -mtune=skylake-avx512`.
- 32 deterministic DNA input strings per configuration, four loops per
  sample: 128 input windows and 1280 output seeds per method/sample.
- Seven samples per method/configuration. Method order rotates between
  samples. Every method receives one untimed warmup before each sample.
- Monotonic wall clock, divided by 128 to give microseconds per window.
- Random tables are initialized outside timing. The same 32 inputs are
  used by all methods within a configuration. The harness PRNG starts at
  123456789; its deterministic correctness phase runs before input creation.
- No external experiment datasets are required. CPU frequency, contention,
  and cache state can affect results on subsequent runs.

The benchmark prints all individual samples as `# sample,...` records.
Committed data are [median results](r10-results.csv) and
[all 112 timing samples](r10-samples.csv). The four summary medians were
checked against the corresponding seven raw samples for every method.

## Reproduce

```sh
make BUILD_DIR=build/pivots-fast \
  CFLAGS='-O3 -std=c99 -Wall -Wextra -Wpedantic -mavx512f -mavx512bw -mavx512vl -mtune=skylake-avx512' \
  test check-one check-pivots
taskset -c 0 build/pivots-fast/bench-pivots --r10
```

Choose another permitted logical CPU if CPU 0 is unavailable. Without
`--r10`, the harness runs its broader historical parameter sweep with
eight inputs, two loops, and three samples. All modes now warm every
method equally before timing. Historical values in `pivots-results.csv`
predate this focused run and retain their original measurement protocol.

## Changes included in this commit

- Added the specialized one-substitution/E-deletion API and its exact
  scalar/SIMD implementations, tests, and benchmark.
- Added the shared-pivot one-deletion/E-substitution APIs, table generation,
  exact budget pruning, SIMD residue joins, arbitrary-r batching, optional
  workspace reuse, exhaustive checks, and benchmark.
- Documented the boundary-to-pivot order variant, resource ownership,
  supported dimensions, finite-score ties, and performance limitations.
- Added the required collision declaration header previously missing from
  version control, so the committed project builds without untracked files.
- Added this reproducible r=10 run, its raw samples, and a project README.

Existing all-splits algorithms and the linked SubseqHash2 source are
unchanged. Existing user notes, datasets, scripts, the supplied paper,
and the external SubseqHash2 symlink are not part of this commit.
